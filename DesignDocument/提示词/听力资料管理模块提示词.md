### 1.提示词
```markdown
我需要在现有系统中新增一个“听力资料管理”模块，属于内容管理模块下的子模块。该模块主要用于管理“听力资料”，请根据以下的描述完成前后端所有代码的实现。

功能概述：

- 听力资料练习，包括列表、查询、新建、编辑、删除等功能。

- 听力资料需要上传一个音频文件，保存到磁盘的对应目录，保存的位置可配置，数据库中存储音频文件的全路径


该模块的数据库结构如下：
- 表名：`listening_material`
- 字段：
    - id: Long
    - title: String（资料描述）
    - originContent:Strign (听力原文)
    - difficulty: Enum（easy, medium, hard）
    - audioPath: String（听力音频的保存路径）
    - fileSize: Long（文件大小）
    - durationInSeconds: Long（音频时长，单位为秒）
    - create_time: datetime
    - update_time: datetime

具体要求如下：

1. 后端：
    - 使用：Spring Boot + JPA (可以参考当前已有代码的风格)
    - 领域相关代码放在在 domain-content 模块中，application层代码放在application-content中，控制器代码放在interface-content中，数据库相关实现放在infrastructure-db中，事件发布相关实现放在infrastructure-event中
    - 保存音频资料的方式实现的可扩展，目前存储在本地，后续可能会对接OSS或其它存储服务
    - 提供分页查询、条件搜索的接口
    - 提供新增、编辑、删除接口
    - 返回统一响应结构（如 Result<T>）
    - 使用DDD的架构风格实现后端代码

2. 前端：
    - 使用 React 编写页面，组件库可以参考当前已有功能的实现
    - 提供：
        - 列表页（含分页、搜索、编辑、删除）
        - 表单页（用于新增和编辑）
    - 与后端进行完整联调，调用实际接口

3. 其它说明：
    - 表单中 difficulty 使用下拉选择框
    - create_time 和 update_time 后端自动填充
    - 联调后确保完整可用（前端能发起请求并接收到正确响应）
    - 创建听力资料时，上传的音频文件和基本信息一块保存
    - 前后端代码的实现风格和当前项目中已有的代码保持一致
```
